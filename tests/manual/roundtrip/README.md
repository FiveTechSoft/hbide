# Roundtrip harness (manual, interactive)

Proves that dialogs generated by DsnGenCode() write the final control
values back to their variables when the dialog ends - the failure mode
Commander hit in its own dialogs (RADIOGROUP value not applied). The
automated suite cannot drive an interactive GET read, so this harness is
run by hand with real keys/mouse; the value check reads a file written
after `oDlg:Activate()`, not the screen.

## Generate the harness

From the repo root:

    hbmk2 -quiet -o/tmp/gen_roundtrips tests/manual/roundtrip/gen_roundtrips.prg \
        designer.prg hbwindow.prg hbmenu.prg hbbutton.prg
    /tmp/gen_roundtrips

This writes six files into /tmp: `radiotest_run.prg` + `runradio.prg`,
`listtest_run.prg` + `runlist.prg`, `mixtest_run.prg` + `runmix.prg`.
Each `*_run.prg` is the generated dialog with one instrumentation line
appended after `oDlg:Activate( GetList )` that writes the control values
to `/tmp/{radio,list,mix}_result.txt`.

## Build and run one case

    hbmk2 -quiet -o/tmp/runradio /tmp/runradio.prg /tmp/radiotest_run.prg \
        hbwindow.prg hbmenu.prg hbbutton.prg
    /tmp/runradio        # run inside a real terminal (xterm)

RadioTest (`First/Second/Third`, initial nOpt=1):

- keyboard: Shift+Tab to the group, Down to select `Second`, Tab, Enter
  on OK -> `/tmp/radio_result.txt` must be `nOpt=2`
- mouse: click `Third`, click OK -> `nOpt=3`

ListTest (`Alpha/Beta/Gamma`, initial nSel=1): same driving ->
`nSel=2` (keyboard) / `nSel=3` (mouse).

MixTest (GET `cName` width 15 + CHECKBOX `lEna`):

- keyboard: type `Antonio`, Tab, Space on the checkbox, Tab, Enter ->
  `cName=[Antonio        ] lEna=T`
- mouse: click the checkbox, click OK -> `lEna=T`

Any mismatch (stale initial value, dead click) reproduces the roundtrip
bug and must be fixed in the generated code or the control libraries
before shipping codegen changes.
